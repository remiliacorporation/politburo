## Deliverables (up to 4 PRs, each under about 500 lines)
PR 1 (docs, design/benchmarks.md): the measurement design. Define a record 'bench-run@1' with: run id, level (sprite|mob|task|pr|spawner), parent id, task or brief id, repo, model (provider/name), thinking level, start and end (UTC), wall seconds, active seconds (time not waiting on a tool or a human; define the rule), turns, tool calls, tokens in / out / reasoning / cached (null when unavailable), cost micros when known, outcome (done|failed|blocked|canceled) with reason, files changed and lines changed (from the DIFF), review rounds, check result, and a complexity block. Complexity: (a) a qualitative rating 1 to 5 plus S/M/L and a one-line reason, written by whoever writes the brief BEFORE the run (rubric in the doc: scope, number of files and components touched, design decisions required, risk class, novelty), and (b) computed proxies after the run (files, lines, review rounds, failed checks, retries) so the rating can be audited and a regression of rating against proxies can be fitted later. Roll-up rules: sprite records are the leaves; mob, task and PR records sum their sprites and add the mob's own wall time; tokens of Claude mob sessions stay null. Privacy: store counts, ids and times only; never prompts, outputs, file contents or credentials. How a benchmark is then made: a fixed task set with a golden check, run across models and thinking levels, compared on pass rate, time and tokens (specify the shape; building the suite is a later PR).
PR 2 (tools/bench/, scripts and tests, no packages/board changes): sprite-usage.mjs reads one sprite's /tmp/sprites/<name>.jsonl, .rc and .out and prints one bench-run@1 JSON line (level sprite); a roll-up script that sums sprite records into mob/task/PR records; fixtures from a REAL sprite log (strip any prompt/output text and any path or credential before committing; record only the field shapes) and tests that fail when a field is dropped, when two models in one log are summed together, when tokens are double counted across restarts, or when a log has no USAGE lines (tokens null, never 0).
PR 3 (ingest and report): write bench-run@1 records to the board (the Politburo way: a block on the task's thread or a swarm/bench channel; choose and justify; use the existing handle, no new API) and a report script that prints, per model and thinking level: runs, pass rate, median wall seconds, median and p90 tokens, tokens per changed line, grouped by complexity rating. Test on a local board in-process.
PR 4 (only if time): the shape of the first benchmark suite as a design addendum plus the smallest runnable task set (3 tasks with golden checks, from tasks this repo actually did) and a runner that executes them through sprite-start with a chosen model.
Invariants for review: no prompt, output, file content or credential in any committed fixture or record; unknown tokens are null, never 0; a log with two models is never summed into one; every number in the report is traceable to a record id; layering (the board is reached through a handle; no new route).
Final message: mob id first line, every PR link with head sha, review results, pnpm check counts, an example bench-run@1 record from a real sprite of yours (counts only) and what was not verified.
