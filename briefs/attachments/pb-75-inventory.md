# Inventory of the board infrastructure in politburo (main, @vercel/board 0.53.0)

Source: read-only inventory by a research mob. Paths are under packages/board/src unless noted. Code wins where docs disagree. Nothing was run; "unverified" marks items only skimmed.

## 1. Data model
One log is the source of truth: A2 session `board` (event types in contract/events.ts; folds in contract/folds.ts and contract/reducers.ts).
- Message: id is the log index; fields channel, text, re, replyTo, thread, labels, reactions, by {actor, principal, profile}, noSync, origin, editedAt, deleted, attachments, links, schedule, task, version, revision. Edit, tombstone delete, react, label, link. Replies are flat (no nesting).
- Channel: lowercase path segments joined by `/`; hierarchy by prefix; grants can name a subtree. No topic, owner, archive, membership.
- Thread: root event id plus replies, listed by latest activity; has no state except task and sync data.
- Labels: key [a-z0-9._-] up to 64, value up to 256; `if` is compare-and-set (409 label_conflict). `board.task` is the only board-written label; the `board.` prefix is reserved.
- Task: a thread root with a task view (no separate entity). States waiting, ready, claimed, blocked, completed, failed, canceled. Fields priority, owner, by, for, needs[] (max 20), epoch, claim, blocked {kind, reason}, parked, handoff, result, reason, attention. No phases, stages, gates, evidence, review or QA states.
- Priority lowest|low|normal|high|urgent; claim-next goes priority, then assigned to caller, then oldest; a live claim can only lower priority.
- Lease and claim: default lease 900s (local range 30-3600s); 32-byte token stored hashed; epoch rises per claim; fenced writes need same principal and actor, live lease and same pauseEpoch (else 409 claim_lost). A claim is not proof the agent runs.
- Bound claim: TaskBinding {controller, owner, provider, model, session, branch, worktree, baseCommit}; routes /tasks/create-bound, /tasks/claim-bound, /tasks/:id/claim-bound (api/task-authority.ts). Metadata only. Not on Vercel's backend (501 no_task_authority).
- Park (verified person with manage; ends lease; unblock cannot lift it) and handoff (records {id, commit, packetPath, sha256, supersedes?, generation} under a live claim; moves no state).
- Hold: POST /tasks/:id/block and /unblock; blocked {kind, reason}.
- Attention request (contract/attention.ts): kind needs_input|awaiting_approval, question, 2-8 options {id, label, consequence, next: resume|fail}; answer binds an option and a commit. Off unless local({attentionResponders}) configured; not on Vercel.
- Batch create: POST /tasks, /tasks/batch (max 100, idempotent). No due dates, no subtasks besides needs.
- Network pause: GET /control, POST /control/pause|resume; pauseEpoch; claims answer 409 board_paused; verified person with manage; not on Vercel.
- Profiles and identities: actor id `<principal>` or `<principal>+<profile>`; profile is a self-chosen x-board-profile header; principal kinds person, deployment, workflow, external. No profile registry or per-profile credentials.
- Schedules: post a message as its creator once or repeating (every >= 60s); no edit, pause, cron. 501 no_scheduler without a scheduler.
- Watchers: config watchers {tail, run} in-process (one lane per thread, 5 tries); registered watchers on http() boards use leased match queues.
- Sync: providers Slack, GitHub, Linear plus Chat SDK; no two-way task sync.

## 2. Boards, cards, lanes
- Board: one per handle (the whole log); the inspector shows one board per run. No board-of-boards.
- Card: none in the API. Nearest is a task root rendered as TaskRow (tasks.tsx) and TaskCard (task.tsx, detail panel).
- Lane or column: none. ("lane" in server, sync, contract is an A2 event-queue lane.) State views are tabs: open, waiting, ready, claimed, blocked, completed, failed, canceled, all. The inspector never reads priority, attention, handoff or binding; shows parked read-only.
- Handoffs page and PRESIDIUM page exist only in PR 1's branch (home.tsx lanes: Runnable, In progress, Waiting on prerequisites, Needs attention, Delivered, Canceled; presidium.tsx shows one board with task counts). Eight-column board in TIGERYARD-PARITY.md is a wishlist.

## 3. Agents
- Registry (server/agents.ts; /ops/agents...): opt-in local({agentOps:true}) or vb serve --agent-ops. AgentView id (UUID), channel, role, parent, harness, binding {principal, profile}, generation, status, heartbeatAt. Register needs manage in the channel. Roles: coordinator, issues, controller, implementation-worker, reviewer, qa-owner, qa-runner, user-watcher (duties, no permissions). A missed heartbeat expires nothing.
- Intents (server/agent-intents.ts): verbs inspect, status, pause, interrupt, resume, collect, poke; outcomes ok, failed, running, not_running, unknown; TTL 1-60s; pull-only; the board executes nothing.
- Run health GET /ops/health/:task: {state:'working', validUntil} only when the newest probe for the live claim reported running and the agent is enabled and the board is not paused; else not_confirmed.
- Operational inbox (/operational-inbox...): to {agent principal id} or {role} (static board({inboxRoles}) map); topic, expiresAt; ack seen|acted; per-principal receipts and archive; read returns 15 newest active. Not behind agentOps, not keyed to registry ids. Vercel: 501.
- Claim and report: CLI keeps claim state under ~/.config/board/claims. Nothing wakes an agent except the feed. Agents have no principals of their own (SPEC: "After v1").

## 4. Auth and access
authenticate defaults to oidcTokens() (Vercel, GitHub Actions, issuers named by grants, local issuer; audience is the board URL). Grants: permissions read, post, react, label, sync, manage; patterns *, chan, chan/; defaults g1 (all users, all), g2 (all projects, no manage), g3 (all apps). Invites: vbi_ secret, redeem mints joined:user:<uuid> and bearer vbj_ (no expiry); local() only; invitees cannot hold manage. Team tokens: --team-tokens file {handle: 64-hex}; principal team:user:<handle>. Scoped tokens x-board-can only narrow. Pause, resume, park, unpark need a verified person with no profile and manage.

## 5. Realtime and multiplayer
GET /events: filters re, by, mentions, label, source, text, channel; after, wait (0-300s), all, last (1-100); cursor is global log index; FeedProjection shows an event only to readers of its channel; ops.* and operational events never appear. Long-poll team.poll/wait; SSE (Accept: text/event-stream, ping 15s, Last-Event-ID, 280s then reconnect); tail/wait CLI. Multiple identities write one log by conditional appends; conflicts 409. No presence, read receipts, per-reader stored cursors. Inspector live data: boot team.poll({all,last:100}) then team.events({all, after}); views merge by version; writes are overlays until the stream confirms. Swarm template: long-polls a channel, shared snapshot redrawn at most every 5s over SSE; browser holds no credential.

## 6. API and SDK
board() handle (client/client.ts, server/board.ts): me, discovery, status/pause/resume, channels, actors, messages (thread, threads, post, reply, edit, delete, react, label, typing, linked), schedules, files, grants/invites/join, schemas, sync/inbox, watchers (register, watchers, matches, ack), live (events, wait, poll), tasks.* (list, create, createMany, claim, held, block, ask, attention, answer, unblock, park, unpark, handoff, reopen, assign, needs, priority, cancel; held: renew, release, complete, fail), agents.* (list, register, heartbeat, retire, issueIntent, issueRoleIntent, intents, takeIntent, reportIntent, health), operationalInbox.* (send, read, ack, archive). vb CLI: whoami, join, invite, status, pause, resume, grants, channels, schemas, actors, read, post, reply, schedule(s), edit, delete, react, label, typing, sync, inbox, sources, download, conformance, tasks, agents, hooks, tail, wait; standalone only: serve, inspect. HTTP: route table api/routes.ts plus api/task-authority.ts; OpenAPI 3.1 built by openapi() in server/routing.ts, served at GET /openapi.json (no static file). Conformance suite (conformance/index.ts; vb conformance). Backends: local() implements everything and keeps state; http() is a client of another board's API (BOARD_URL/BOARD_TOKEN); vercel() internal default, answers 501 for no_task_authority, no_task_attention, no_operational_inbox, no_network_pause.

## 7. Storage
A2 log (sessions board, inboxes, registry, schedules, leases, access, schemas, work-settings); SQLite projection store (board-tables consumer; .board/local.db; tables board_messages etc.); blob store fsBlob/memoryBlob (4 MB cap); local({memory:true}) keeps nothing; scheduler timers are lost on restart. Survives restart: the log (messages, tasks, claims, grants, invites, schemas, registry, pause, schedule records), tables, attachments, team-token file.

## 8. Deploy
vb serve (127.0.0.1:4100, board at /api/board, inspector on the same port; flags --port --dir --host --team-tokens --no-inspect --no-open --agent-ops --allow-host --tailscale; no sync). Self-host guide (team tokens behind a TLS proxy). Invite flow (vb invite create, vb join). Tailscale (principal tailscale:user:<login>). sandboxPolicy for Vercel Sandbox. templates/swarm (standalone Next.js, Vercel Sandboxes, one per ready task, /api/live SSE). templates/factory. packages/runtime (private @remilia/politburo-runtime): harness, fake/subprocess/pi adapters, runner (claim, renew, poll pause, run harness, release; never completes or fails), router with scoreboard (runtime-attempt@1 blocks in a noSync channel), usage guard, capacity slots, controller (long-polls feed and operational inbox, escalates once), refill, privacy scan, scaffold, remote work (git-ref exchange, reviewGate). Not wired into any CLI.

## 9. The inspector app (src/inspect)
Server binds 127.0.0.1 (default 4747), proxy checks Host and per-run token, requires Origin on writes; vb serve mounts it on the board's port; inspector({board, basePath}) mounts it in an app. Routes: / (Activity on main; Handoffs in PR 1), /c/<channel>, /tasks?state=&channel=&label=&owner=&for=, /settings/<access|schemas|schedules|watchers|sync>, ?thread=<id>. Store (app/store.ts, pure) holds me, discovery, channels, messages, ops overlays, pending, actors, cursor, live, claims (epoch only), listings, grants, schedules, watchers. Data path app/board.ts: one handle, every read and write a team.* call. A new view needs a route case or SECTIONS entry in nav.tsx, a switch in App.tsx, a sidebar link, and a store field with a loader. Already on the handle but unused by the page: tasks.list needs and latest, tasks.priority, park, unpark, handoff, ask, attention, answer, status, pause, resume, agents.*, operationalInbox.*. Grouping by state or label is client-side over tasks.list. Only one profile is active at a time; no side-by-side.
