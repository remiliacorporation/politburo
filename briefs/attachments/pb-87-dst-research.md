# DST research report (mob 24-FOX, pb-79), condensed

Finding: with the memory store the board is already nearly deterministic. A2's memory store resolves in microtasks and its append runs the head check and the insert in one synchronous section (experimental-a2/src/store-memory.ts ~666-722). What is missing is control over WHICH operation resumes at an await between a check and the append. A custom cooperative scheduler on store.log.append plus a fake Date reproduces the PR 20 and PR 21 race classes with no product changes.

## Nondeterminism and seams
- Wall clock: bare Date.now() across server/tasks.ts (~25 sites), agent-intents.ts, trust.ts, policy.ts, auth.ts, tokens.ts, schedules.ts, operational-inbox.ts, agents.ts, a2.ts, serve.ts, blob.ts. Seam: vi.useFakeTimers({ toFake: ['Date'] }). The memory store also takes a clock (store/memory.ts, testClock() in test/harness.ts); sqlite({path}) takes none.
- Timers/scheduler: scheduler/local.ts, lease arm in tasks.ts, writes.ts, board.ts, registrant.ts, tails.ts. testBoard() runs with no scheduler, so no lease.due fires; expiry is checked by the clock at append, so a virtual clock is enough.
- Randomness: tokens and ids (tasks.ts, writes.ts, a2.ts, agents.ts, agent-intents.ts, trust.ts, blob.ts, tails.ts) do not steer interleavings. Retry jitter in writes.ts (~669, Math.random()*5*tries ms) only delays arrival at a gate; a gated driver is insensitive. Byte-identical replay would need an ids pass-through in store/memory.ts and store/sqlite.ts (the option exists in A2 stores).
- Async check-to-append gaps: writes.ts ~640 (appendFrom: look, then appendIfLast ~950), ~661-675 (whileHeadMoves, 10 tries), ~599 (untilApplied), tasks.ts ~168 (due), ~270 (change). Seam: wrap store.log.append on the injected BoardStore (PR 20's own tests do this in expireOn).
- Cross-session gap (PR 21): access session (trust.ts ~449-571, ifLastIndex) versus board session; a conditional append guards only its own session. Seam: store.fence on PR 21; wrap fence.access and fence.guarded so the driver knows an op is blocked on the lock.
- In-append check (PR 20): store/append-guard.ts runs the check inside A2's clock.now() during the insert: the correct fix shape, nothing to inject.
- SQLite: store/sqlite-db.ts (node:sqlite, synchronous); the A2 SQLite log store is a separate adapter; transactions were not gated (unverified).
- Files: server/blob.ts fsBlob put writes data then a .type file (non-atomic); memoryBlob() available; BlobStore is an interface so a fault-injecting wrapper works. CLI claims: cli/claims.ts (readdir, rename, unlink, writeFile, process.pid, randomUUID); seams memoryClaims, tokenClaims, XDG_CONFIG_HOME (client/join-config.ts); vi.mock('node:fs/promises') worked; a cleaner seam is an fs parameter on fileClaims.
- Process state: server/identity.ts (process.cwd), client/node.ts, env reads in server/index.ts and client/node.ts; set per seed. Network: backend-http.ts options.fetch, server/tokens.ts OIDC discovery (global fetch), client/client.ts; injected fetch and JWKS exist; a deterministic fetch with redirect semantics is needed for finding (f). jose verification is real async crypto with injected JWKS; the driver absorbs it by waiting for quiescence.

## Harness design (~100 lines core: Sim)
- rng(seed): mulberry32. Sim.gate(label): called by a wrapper around store.log.append; parks the caller until the driver picks it; parked callers sorted by op index so the choice never depends on arrival order.
- Sim.run(ops): each op gets an AsyncLocalStorage index and parks at a synthetic start gate. Driver loop: wait until every op is parked, blocked on a known lock, or done; choose one parked op by seed; optionally move the clock before releasing it; release; repeat.
- Sim.block()/unblock(): mark an op waiting on the fence (without it a lock waiter looks still running and the driver mis-schedules; the first run did exactly that). Sim.kill(): simulate process death (op never continues, counts as finished).
- Clock policy, boundary-biased: with probability 0.6 jump to a live lease's until plus one of {-1, 0, +1, +1000} ms.
- Fault injector implemented: append reordering, clock jumps, process kill. Not implemented (one wrapper each): append failure after commit (lost ack), delayed access-log write, partial write, lost response, blob put crash between data and .type, HTTP redirect/5xx/duplicate delivery.
- Operations: claim, renew, submit, release, takeover claim, scope, stage, assign, needs, cancel, grant revoke, reopen, finish macro. Pause/resume and expire not generated.
- Invariants as history oracles over landed events (never consult product code): I1 no task.renewed, task.work_submitted (names the epoch ROUND, not epoch), task.released or task.completed lands at or after its lease's until, none lands with a stale epoch; I2 no task.claimed lands while another lease is live; I3 no task event authored by a revoked scoper lands after grant.deleted (the event is grant.deleted, not grant.revoked); I4 a task in ready never has an unfinished prerequisite; I5 a saved claim that was put is never lost to a stale drop. Not implemented: no reader learns what grants hide; completion never lands on an expired verdict (same pattern as I1 over evidence events).

## Approach recommendation
Custom cooperative scheduler for interleavings (controls exactly store.log.append and the fence) plus fast-check (a free devDependency, not in the repo today) for sequential generation, shrinking and replay by seed; fake Date; wrappers for fence and fs. No paid service (Antithesis rejected), Rust tools (madsim, turmoil) do not apply. FoundationDB/VOPR/Jepsen are the ideas behind it; the oracles are Jepsen-style history checks. Cost: library ~120 lines plus fence and fs wrappers; suite 4-6 test files of 70-100 lines (one per race class); optional seams: ids pass-through in store/memory.ts and store/sqlite.ts, and an fs parameter on fileClaims.

## Risks
Memory store only (A2 SQLite ifLastIndex transaction never gated); A2 internals (drain, lapse timers, Math.random jitter in server.ts) stay real (trace hashes show no schedule effect, empirical only); quiescence is observational (an unknown lock shows as a stalled error after 5 s); not covered: sync providers, multi-process boards (the fence is in-process by design), real network stack; each oracle encodes a reading of the spec (I3 treats any scoper event after the revoke as a bug; not checked against SPEC.md); the harness files were throwaway (347 lines) and did not run under CI.

## Plan from the report
