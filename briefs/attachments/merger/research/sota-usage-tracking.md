# Exact resource tracking for Politburo

Research checked 2026-11-22 against public documentation and local pi 1.5.2. No model was run for this research. Vendor docs describe current releases, not necessarily the versions installed on each worker. No live account entitlements or telemetry paths were tested.

## Executive summary and ranked recommendations

1. **Make the office Mac the accounting authority.** Put an append-only spend ledger and an atomic reservation/admission service beside `vb serve`. Use a single authority across repo boards. The inspector and board event feed display projections, not competing balances. Do not buy an observability service or start by deploying a large tracing stack.
2. **Collect Claude Code request events locally and in cloud mobs.** Current Anthropic docs explicitly support OTLP export from Claude Code on the web. Join on the remote session ID and require a pre-assigned task attempt. Use the token fields on `claude_code.api_request`, not USD fields, status-line context counters, or subscription percentages. Tail the local transcript as corroboration and a scoped fallback. Pilot cloud telemetry first; Git/PR mirroring alone cannot measure the mob's model.
3. **Put every sprite behind the pi supervisor.** Read final usage events, capture compaction and extension usage, use the actual provider and model, and spool before sending. Test the actual Cursor fallback, separately from a normal Codex route. Do not silently accept missing data or convert it to zero.
4. **Gate dispatch and enforce where you control execution.** Reserve against swarm, repo, task and worker limits before launch, and again before each controlled paid call or bounded work unit. Add deadlines, concurrency limits, lease fencing and a stop control. An already-running Claude Code cloud mob is observable but is not a hard token or dollar boundary. Give it small bounded assignments or move strict-budget work to a runner and request path you control.
5. **Keep three separate meters: provider-reported tokens, priced usage, and settled charges.** A complete set of final provider-reported usage counts can be exact for the calls you observed. Client-priced dollars are not an invoice. A fixed subscription fee has no exact per-task allocation. Five-hour and weekly percentages are shared quota signals, not token counters. Unknown usage is neither free nor an estimate of zero.

**Bottom line:** no additional paid service is needed. The present stack cannot guarantee exact settled cost or complete token accounting for every tier under every failure. It can give exact reported counts where covered, explicit gaps elsewhere, exact admissions in Politburo, and hard per-request ceilings only on suitably bounded paths. Sources: [Claude Code Monitoring](https://code.claude.com/docs/en/monitoring-usage.md), [Claude Code Costs](https://code.claude.com/docs/en/costs.md), [SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking.md).

## 1. Claude Code: what each surface actually measures

**Subscription quota.** Use claude.ai Settings > Usage, `/usage`, or the status-line `rate_limits.five_hour` and `.seven_day` fields (`used_percentage`, `resets_at`). The status-line docs limit those subscription fields to Pro/Max/Ultra and only after a first API response; windows can be absent independently or expire. `/usage` can expose more plan/scoped rows and can display stale data after a rate limit fetching usage. Recent TS Agent SDK versions additionally expose structured `/usage` on `SDKAssistantMessage.usage_report` (`session.model_usage`, `rate_limits.limits` and `extra_usage`); the type is experimental. Its `rate_limit_event` reports allowed/warning/rejected status and optional reset/utilization, not a complete quota snapshot. Plan windows are shared across eligible account activity, including cloud; other devices and users of an allocation can burn headroom. Percent and reset are exact **as published snapshots** of plan utilization, not exact tokens or per-job draw. Server-reported monthly usage-credit spend is an account amount, not a task amount. Store observation time, reset, account alias, meter kind/scope and freshness. Do not scrape private endpoints, turn percentages into tokens, or rotate identities to evade limits. [Status-line limits](https://code.claude.com/docs/en/statusline.md#rate-limit-usage), [plan costs and limits](https://code.claude.com/docs/en/costs.md), [SDK usage report and rate events](https://code.claude.com/docs/en/agent-sdk/typescript.md#sdkusagereport), [cloud usage](https://code.claude.com/docs/en/claude-code-on-the-web.md).

**Gateway/API-level collection.** If calls use a supported API gateway you control, collect final response usage and request IDs there, including actual cache and server-tool units when present. Anthropic's uncached input, cache write and cache read are disjoint; total input is their sum. Do not add cumulative stream updates. Count-tokens preflight is an estimate, not a strict upper bound. API-side OTLP and Claude Managed Agents are separate from Claude Code on the web; Anthropic explicitly describes best-effort trace delivery. Do not assume you can put a gateway in the subscription path or reuse personal auth programmatically; check provider terms and supported login before migrating. [Messages schema](https://platform.claude.com/docs/en/api/messages/create.md), [counting](https://platform.claude.com/docs/en/build-with-claude/token-counting.md), [gateway](https://code.claude.com/docs/en/llm-gateway.md), [API OTel](https://platform.claude.com/docs/en/manage-claude/opentelemetry.md), [SDK auth policy](https://code.claude.com/docs/en/agent-sdk/overview.md).

**Tools on top.** `ccusage` reads local Claude project JSONL, including configured alternate directories, and provides session/day/weekly/block views. Its current parser handles request/response dedupe, replay and cache TTL/iteration details. Auto uses logged `costUSD` when present, otherwise prices tokens. Display keeps logged cost only. Calculate prices tokens against a catalog. None reads settlement; inferred five-hour blocks are not official quota meters. Claude-Code-Usage-Monitor uses local JSONL and, in current releases, official status-line snapshots with provenance and forecasting. Use them as offline diagnostics and test oracles, not a spend/limit service. [ccusage source](https://ccusage.com/guide/claude.md), [cost modes](https://ccusage.com/guide/cost-modes.md), [blocks](https://ccusage.com/guide/blocks-reports.md), [monitor](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor).

### Deploy the Claude adapter

- Set `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_LOGS_EXPORTER=otlp`, and optionally `OTEL_METRICS_EXPORTER=otlp`. Set `OTEL_EXPORTER_OTLP_ENDPOINT` and protocol (`grpc` locally, or `http/protobuf` with HTTPS through ingress); per-signal endpoints/protocols are supported. Default logs/metrics batches are 5s/60s. Keep `OTEL_METRICS_INCLUDE_SESSION_ID=true`; optionally enable `OTEL_METRICS_INCLUDE_REPOSITORY` on supported releases, but use the board's repo ID for charging. Set static `OTEL_RESOURCE_ATTRIBUTES` for launcher/site identity, not an evolving task label on a long-lived process. Traces additionally need `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` and `OTEL_TRACES_EXPORTER=otlp`. Leave prompt, response, tool details/content and raw API-body logging off. Apply an ingest allowlist; default logs can still carry account/user metadata. Raw API-body inline/file exports can carry usage but expose conversation content and are unnecessary. [OTel configuration](https://code.claude.com/docs/en/monitoring-usage.md).
- For web mobs set variables in the cloud environment or eligible server-managed `env` settings. A setup script's `export` does not reach Claude Code. Local settings on the Mac do not configure the VM. Explicitly allow the collector domain from the cloud environment. Group by `ccr.session.id` (`CLAUDE_CODE_REMOTE_SESSION_ID`), not the in-process `session.id`, which can change. Keep both. A cloud environment edit may only take effect on VM restore/rebuild; it is not the live budget switch. [Cloud telemetry](https://code.claude.com/docs/en/monitoring-usage.md#telemetry-from-cloud-sessions-and-claude-tag), [environment variable timing](https://code.claude.com/docs/en/cloud-environments.md#set-environment-variables).
- Do not expose `vb serve` to the internet for this. Use a narrow, authenticated, write-only HTTPS receiver on an approved network path. Anthropic warns that shared environment variables aren't a safe place for collector credentials, and network secrets are **not** injected into Claude Code's OTLP exporter. For authenticated native export, use the documented server-managed configuration, including destination locking, if the org has it; verify it. A separate wrapper upload can have its own supported limited-scope authorization. If the office cannot support a safe path yet, keep the board private and mark native cloud spend unknown. A Git/PR mirror can carry lifecycle facts and, with a deliberately designed private artifact path, sanitized delayed wrapper usage; it cannot reconstruct cloud inference from diffs or PR timestamps. An eligible Team/Enterprise self-hosted environment (public beta) is another option, or run headless workers locally. Neither is equivalent to a guaranteed per-request ceiling out of the box. [Managed OTLP settings](https://code.claude.com/docs/en/monitoring-usage.md#how-managed-settings-lock-the-otlp-destination), [cloud network restrictions](https://code.claude.com/docs/en/cloud-environments.md#network-access), [self-hosted environments](https://code.claude.com/docs/en/self-hosted-environments.md).

## 2. Sprites: pi, OpenAI Codex and Cursor

### pi 1.5.2

Local `pi --help` confirms `--mode json`, `--mode rpc`, `--session`, `--session-id`, `--session-dir`, and `--no-session`. The installed `docs/json.md`, `docs/rpc-commands.md` and `@earendil-works/pi-ai/dist/types.d.ts` were checked without entering a session. Public equivalents: [JSON event stream](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/json.md), [RPC commands](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc-commands.md), [session format](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/session-format.md), [usage types](https://github.com/earendil-works/pi/blob/main/packages/ai/src/types.ts).

- Each line is a JSON event. Capture one final assistant `message_end.message` per response, with `provider`, `model`, `api`, `usage`, timestamps and stop status. `message_update.usage` is the latest **cumulative per-response** snapshot; it may be zero until completion. `turn_end`/`agent_end` can repeat messages: do not sum them. Give each response a wrapper sequence if a provider request ID is not exposed. A canceled/error frame with no final usage is a coverage gap, not a zero receipt. A canceled response may still carry reported usage; preserve the provenance and completion state.
- `usage` has `input`, `output`, `cacheRead`, `cacheWrite`, `totalTokens`, optional `cacheWrite1h` (subset of `cacheWrite`) and `reasoning` (subset of `output`), and a `cost` breakdown. `cost.totalFromProvider === true` distinguishes provider-reported billed total where supported; the component prices can still be catalog-derived. Otherwise the total is a catalog estimate. The standard OpenAI/Codex Responses adapter splits cached input out of input, takes final provider usage, and calculates catalog cost. Keep raw bucket semantics, not just `totalTokens`. [Responses usage mapping](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/openai-responses-shared.ts), [Codex adapter](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/openai-codex-responses.ts).
- Capture `compaction_end.result.usage`, `tool_execution_*`, retry events, and any separate branch summaries/tool-reported usage. Prefer a pi extension or SDK accounting boundary for extra calls a tool or extension makes; do not assume the JSON assistant stream sees them. In RPC, `get_session_stats` includes assistant messages, tool usage and compaction/branch summaries across saved history. Use it or a local saved session as a reconciler, not another charge. Save a per-run cursor/baseline on resume/fork. If you use JSON only, document which auxiliary calls cannot be seen. No additional model calls to read the stream or stats.
- `fallback/codex-cursor` is a route, not a spend identity. Record every actual provider attempt, resolved model, fallback reason and auth/billing category. The installed base package and public sources do **not** verify the private fallback adapter's handling of `gpt-6.2-sol`, Cursor token fields, hidden retries or dollars. **Unverified** until the wrapper has fixtures from that route and the Cursor join described below. A fallback may have a failed first call and a successful second one; count both if usage is reported. Require a fresh reservation on every fallback.

### OpenAI Codex CLI (if the sprite actually invokes it)

- `codex exec --json` emits `thread.started` and `turn.completed.usage`, including input, `cached_input_tokens`, output and `reasoning_output_tokens`; current source also has `cache_write_input_tokens`, which defaults to zero when deserializing a record without that field. Counts are for the turn, not cash charges or a request ledger. Cached input and reasoning output are components, not extras to add to total input/output. A `turn.failed` or broken stream need not give final usage. Do not apply this schema to a pi adapter merely because it uses Codex models. [Noninteractive Codex](https://developers.openai.com/codex/noninteractive.md), [event source](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs).
- For a managed interactive integration use `codex app-server`: `thread/tokenUsage/updated` for thread usage snapshots, `turn/interrupt` for control, `account/rateLimits/read` and `account/rateLimits/updated` for account percentages, windows and optional credits. Distinguish thread totals from last usage and turn deltas. TUI `/status`, `/usage` and footer are human diagnostics; the CLI also has optional OTLP logs. None is a provider settlement feed. Reading existing data needs no model; starting `exec` does. OpenAI API organization Usage/Costs can reconcile API spend at its available bucket grain, not ChatGPT allowance or arbitrary Codex thread IDs. [App Server](https://developers.openai.com/codex/app-server.md), [CLI commands](https://developers.openai.com/codex/cli/reference.md), [OTel configuration](https://developers.openai.com/codex/config-advanced.md), [Codex pricing](https://developers.openai.com/codex/pricing.md), [OpenAI org Usage/Costs](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/).

### Cursor

- **Standalone CLI:** documented `cursor-agent --print` output formats `json` and `stream-json` provide `session_id`, init model, result status, duration and tool events. ## 3. State of the art: what to copy and what not to copy

**Traces describe causality, not ownership or settlement.** Use W3C trace context and OpenTelemetry GenAI spans for workflow, agent invocation, model call and tool execution. One task attempt can parent multiple agent invocations. At an async handoff propagate `traceparent`; use links for fan-in, retries across traces, or a remote session that starts its own trace. Claude Code currently accepts inbound `TRACEPARENT`/`TRACESTATE` in SDK and print mode, not interactive mode; it can pass `TRACEPARENT` to Bash/PowerShell tools with tracing enabled, subject to gateway settings. For interactive and cloud, board IDs are the join even when parent spans cannot be forced. Use explicit board IDs rather than indexing all task IDs on metric series. Pin a GenAI semantic-conventions version. Normalize Anthropic input for `gen_ai.usage.input_tokens` as uncached + cache read + cache write, keeping cache breakdown attributes as subsets. Claude Code does not emit those `gen_ai.usage.*` fields itself. No trace sampling or fan-in rollup should affect the ledger. ## 4. Politburo proposal

### Keep accounting and control on the office host

Local design inputs: `design/swarm-architecture.md` has a pre-claim `usageGuard` (95% five-hour stop) and separate capacity check. `design/swarm-frontend.md` has the swarm tree, queue and settings. The merger plan assigns mob/sprite reporting and spend to M25/M80 and C11, with Q3 favoring a Git/PR mirror first. Use that mirror for lifecycle reporting if necessary, but keep telemetry transport as a separate, explicit decision. `packages/swarm` owns Python launchers, decoders and transport. `vb serve` owns the grants, task/lease boundary, board-facing API and presentation. Give the accounting writer exclusive ownership of ledger tables. For multiple board DBs, use one accounting SQLite DB on the Mac; repo boards refer to it by `board_id`/`repo_id`. Never sum asynchronously mirrored balances to admit work. If task claim and reservation cannot share a transaction, use a fenced pending-dispatch record with a compensating release, and do not launch until both are confirmed. Start with one Mac process, a single writer, backups and restore tests. No external SQL, tracing or queue service is required.

### Stable identities and one unit of spend

Create `execution`, `session_binding`, `task_attempt`, `reservation`, `policy_version`, `source_observation`, `spend_event`, and `coverage_gap` tables. A `spend_event@1` is one **exclusive** fact: a model response or observed attempt, one resource interval, or a discrete charge/count. Aggregates/snapshots are observations, never automatically additional spend. Suggested fields:

| Fields | Contract |
|---|---|
| `event_id`, `schema_version`, `kind`, `dedupe_key`, `revision_of`, `reservation_id` | Globally unique logical ID; database unique dedupe constraint; append a correcting/superseding record with reason and actor, do not rewrite history. Keep admission reservations out of settled spend. |
| `swarm_id`, `board_id`, `repo_id`, `task_id`, `task_attempt_id`, `lease_epoch`, `exec_id`, `parent_exec_id`, `tier` | Assigned at dispatch. Separate an agent identity, logical session, process incarnation, and work attempt. `tier` is `core/spawner/secretary/mob/sprite` or human/system for non-model facts. Bind immutable ancestry and expenditure owner. |
| `native_session_id`, `remote_session_id`, `native_thread_or_run_id`, `provider_request_id`, `response_id`, `prompt_id`, `process_epoch`, `sequence`, `trace_id`, `span_id`, `parent_span_id` | Optional native evidence and join handles. Namespaced by provider, billing identity and producer as needed. Never use provider session name, cwd, git branch or UTC proximity alone as the task key. |
| `actor_id`, `billing_account_ref`, `provider`, `route_requested`, `model_requested`, `model_actual`, `auth_class`, `service_tier`, `speed`, `inference_geo`, `purpose` | Opaque internal principal/account alias, not a credential. Distinguish main/compaction/auxiliary/review/fallback/etc. Distinguish API, included plan, credits/overage or unknown. |
| `tokens.{input_uncached,input_total,output,cache_read,cache_write,cache_write_5m,cache_write_1h,reasoning}`, `server_tool_units` | Nullable integer counts. Input total and splits are not additive with the component buckets twice. Reasoning is a subset when the provider says so. Record source semantics (e.g. inclusive input), missing values and any provider-specific dimensions. |
| `amount_decimal`, `currency_or_unit`, `money_basis`, `tariff_version`, `pricing_components` | Separate provider-reported charge, later settlement, modeled USD, credit units and unknown. Use decimal strings or scaled integers with explicit precision, not floats. Preserve the exact source amount. Missing price never implies $0. Price at occurrence using a versioned tariff including cache TTL, rate/tier modifiers and non-token fees where documented. |
| `occurred_at`, `received_at`, `started_at`, `ended_at`, `elapsed_monotonic_ns`, `quantity`, `unit`, `status` | UTC for ordering/window membership; monotonic durations within one host/boot. Define use of finish time for response charges and splitting intervals across windows. Include error/interrupt/late/outcome states. |
| `source`, `source_version`, `source_event_key`, `evidence_ref`, `field_quality`, `coverage_state` | Field-level `provider_reported`, `locally_measured`, `provider_charge`, `priced_estimate`, `quota_snapshot`, `unknown` as applicable. Coverage is separate: `live`, `pending`, `closed_reconciled`, `partial`, `unattributed`, `conflict`. Evidence references must not expose prompts, tokens used for authentication, or raw transcripts. |

**Attribution rule.** On a new task attempt create a dispatch envelope with IDs, originating repo, lease epoch, and trace context. Add the envelope reference to the existing structured mail block; leave routing deterministic. First register the local session and cloud remote ID, and keep early telemetry pending until the binding arrives. Bind a hosted mob to one attempt for its life; when a sprite starts it inherits the mob attempt and gets its own execution ID. The spend rollup is sprite → mob → task attempt → task → sponsoring spawner → repo → swarm. Secretary attribution is by routed work or repo overhead; it is not necessary to pretend it executes every child. Keep the runtime launch-parent relationship separately for the physical tree. Report each tier's own and inclusive totals. An interactive core/spawner can cover many tasks: use an explicit lease/prompt binding (`prompt_id` when available), carry it into child execution, and use dedicated task sessions when interleaving cannot be attributed exactly. If one request genuinely covers several tasks, book it once to coordination overhead or a meta-task; any apportionment is a labeled policy, not an exact fact. Never retroactively shift a charge because a task was reassigned or its lease expired. Core's swarm overhead, repo overhead and unmatched items must remain visible in swarm totals.

### Sources by tier

| Tier | Meter and controls |
|---|---|
| **Core** | Local Claude OTLP requests plus local transcript fallback; status line only for quota/context/durations. Launcher records process/turn intervals. Explicit prompt-task binding; otherwise core overhead. Jockey inputs remain manual when not wrapper-controlled. |
| **Spawner** | Same local sources, pinned repo ID and per-prompt task or overhead. Separate each process/resume incarnation. Enforce all further dispatch through the board, not by asking the session to respect a number in its prompt. |
| **Secretary** | Meter deterministic YAML routing by message ID, script monotonic time, CPU and exit state. Record **zero model calls for a script-only route** when enforced by design, not for the entire Haiku session. Meter model triage via Claude OTLP or a controlled headless call. Consider removing the always-on model from pure routing. |
| **Mob** | Native cloud OTLP bound to remote session ID. Provider counts for observed calls, priced USD only. Board launch/start/heartbeat/finish records distinguish task elapsed time and observed active time. Require transport/coverage canary; unknown on failure. Agent-generated summaries or PR events are not token evidence. No exact Anthropic-hosted VM allocation/billing clock verified; Anthropic says there is no separate web VM charge. |
| **Sprite** | pi terminal response/event spool, compaction and tool sources, wrapper timings, optional Codex/Cursor adapter or admin reconciliation. Provider counts only where observed. Charge/control each physical attempt, not the virtual route. The supervisor can stop sprites it owns, not thereby stop parent mob inference. |
| **Jockey and peers** | Board acknowledgement, claim, focused review start/stop and decision events. No model tokens for the human action. Time-to-ack is exact for those events; actual attention is not observable without a defined timer or self-report. |

**Reconciliation and loss handling.** Use one preferred charge source for each execution/interval. For Claude, prefer final OTLP events, match transcripts by provider `requestId` and response ID, and ingest a final transcript fact only for a known uncovered request. If no reliable match, hold conflicts instead of guessing. Save file identity, byte cursor and parse version; tail complete lines, revisit trailing updates, handle rotation and preserve fork lineage. OTLP `event.sequence` resets on process restart and isn't globally unique; don't dedupe on it alone. For pi, use dispatch ID + incarnation + response ordinal (and native IDs if available). A session snapshot can fill a separately identified interval only with a proven baseline and disjoint scope. Do not subtract incomparable maps or assume lower counts mean no spend. Retain sanitized counted observations and provenance; receipt/fingerprint before acknowledgement. Use fsynced wrapper spool, monotonically numbered batches, retries, contiguous ACK watermarks and startup recovery. Captured usage can replay without adding spend. Add source-version checks, heartbeats, gap counters, and late-arrival reconciliation. A healthy heartbeat proves the sender is alive, not that a provider responded or logged every call. Compare event aggregates against independent counters, final SDK/pi totals and eligible provider reports. Track mismatched and unallocated amounts separately; reconcile billing at the report's grain, not by spreading differences over tasks. Redact at the source and again at ingress. Apply grants per repo and role; give runners write-only, run-scoped access and never trust model text as usage or policy. Sanitize/account-namespace native identifiers; retain metadata for an agreed period, not raw conversation bodies.

### Budgets, admission, and emergency control

1. **Policy.** Store versioned rules keyed by scope (`swarm`, repo/board, submitter, tier, task, attempt, account/model), dimension and time window. Include revision, actor/reason, effective/expiry times, hard and warning values, reserved emergency allowance, action, missing-data policy, and permitted model routes. Dimensions: provider tokens by bucket, modeled USD or settled/credit units separately, concurrent runs, dispatch/request rate, wall/active time, tool or CI runs, retries. Use fixed window, rolling window, or task-lifetime definitions with explicit time base. A child cannot raise an ancestor's policy. Read current rules for every admission and renewal. Publish policy revisions and stop flags in the board feed; use compare-and-swap editing for multiplayer. A human override is scoped, expiring, audited and cannot change a vendor limit.
2. **Atomic admission.** Before a lease is given to a worker, the office arbiter checks dependencies, priority, grants, pauses, quota freshness and short/long window headroom, telemetry health, concurrency slots, and every applicable budget. In a single serialized SQLite write transaction require `committed + outstanding reserved + new reservation <= effective ceiling` for every scope and dimension, then reserve and insert an idempotent dispatch intent with deadline and fence. Account windows use the existing usage guard as a separate supply signal: use published 5h **and** weekly/scoped meters where available; schedule a token-free wake/check at reset, but require a fresh snapshot or human decision before lifting a strict pause. No conversion from percentages. Keep a pessimistic reserve for unknown external activity; do not call it spent. Conservative estimates are acceptable for planning reserves only; a strict rule must reserve a real documented worst case or reject. Re-check before side effects and recheck before retries/fallbacks. If a remote start returns ambiguously, reconcile before launching a duplicate. Do not let workers admit through a stale cached policy when disconnected.
3. **Spend and settlement.** Match final events to the reservation; consume capacity once, release only verified unused capacity, and keep outstanding liability until jobs quiesce or go to an explicit unknown-charge state. Lease timeout frees scheduling only after the runner is fenced; it is not proof a remote process stopped. Keep previous liability across a window boundary until settled; account for late billed work in its proper period. An authorized run can spend above a soft estimate; record the overrun and stop new work, not the accounting. For strict limits use a child allocation and gate each actual model request with a conservative, enforceable input/context and max-output bound, bounded retry/fallback count, non-token fee bounds, and no bypass route. Apply RPM/TPM/concurrency rate shaping centrally. No hard cash promise if tariff/billable activity is unknown. A provider cancellation or a local kill cannot unsend a call.
4. **Control.** Use real OS/job boundaries and monotonic timers on local workers and sprites. Drain at a checkpoint, then interrupt/terminate the process group if authorized; verify descendants exit and flush records. Limit tasks/agent fan-out, tools and retries mechanically. `--max-budget-usd` is a secondary brake (post-response, estimate), not the hard gate. For hosted Claude Code, hard-cap **new** launches/dispatches and child sprites via leases. On a running mob, stop feeding it and escalate to the jockey to use the hosted session's controls where available; rehearse and verify cancellation in the canary. The web docs describe [archive](https://code.claude.com/docs/en/claude-code-on-the-web.md#archive-sessions) as removing a session from the sidebar, not terminating it. Do not equate archive, a kill request, or stopped heartbeats with stopped spend. A supported hard per-request stop/control API for these claude.ai/code mobs is **unverified**. If immediate deterministic enforcement is non-negotiable, do not dispatch that job to this surface. Model settings changes take effect at their supported boundary; use the policy service for live edits.

**Inspector and jockey controls.** Show swarm → repo → task → attempt → sessions/calls, and a physical tier tree with exclusive and inclusive totals. Show observed/covered tokens by input/cache/output, modeled USD distinct from billed/credits, committed/reserved/remaining, quota snapshot age and reset, gaps, source drift and current policy version. Show count of unknown requests/blocked attempts rather than invented totals, and last contact for every active job. Pause admissions globally or by repo/task/account; allow drain, cancel, lower concurrency, switch to an approved cheaper model at the next boundary, disable fallback, raise a cap for one attempt, or reassign human review. `stop requested`, `acknowledged`, `exited` and `reconciled` are separate states. Emit structured attention requests only for actionable conditions: pending hard stop, stale telemetry, mismatch, unknown spend, or override needed. Give colleagues their repo views; the jockey gets fleet controls and an audit trail. No overriding physical or provider limits.

## 5. Other resources and definitions

- **Time:** task end-to-end elapsed includes queue and waits. Keep queue, executing, API wait, tool execution, blocked on CI or human, and idle intervals separate. Use monotonic start/stop in a known process and UTC to line up hosts. Sum worker-seconds for consumed effort; take the union of intervals for elapsed active time; do not sum overlapping parent and child wall time as task duration. Heartbeat gaps give bounds, not exact VM lifetime. Collect CPU time, peak RSS, disk/network and VM occupancy when the supervised process/runner can report them. Do not bill inferred hosted VM minutes.
- **Calls and failures:** count provider attempts, successful model responses, hidden/unknown attempts, tool calls by stable call ID, retries by reason, fallbacks, restarts and compactions. Log execution vs authorization separately. No extra token charge for a deterministic tool unless the tool itself invokes a model; tool and model are still different resources.
- **CI:** collect workflow run/job IDs and attempt, start/completion, runner type, outcome and commit SHA. CI elapsed and runner-job seconds are different from billed minutes (which depend on provider accounting). Attach jobs via the specific branch/PR and SHA or task dispatch; count retries, canceled runs and shared jobs once. Aggregate exact billing only where an eligible billing source provides it. [GitHub Actions workflow jobs schema](https://docs.github.com/en/rest/actions/workflow-jobs#get-a-job-for-a-workflow-run).
- **Human and delivery:** attention queue time, explicit reviewer focus intervals or self-report, distinct review rounds, requested changes, approvals, rebases, merges, closes without merge, reversions/reopens and follow-up defects. Link PR outcome to the originating attempts. Compare spend per merged or accepted task with waste from failed/retried attempts as a separate numerator. Avoid lines of code as a proxy for outcome and clicks as a proxy for attention.

## 6. Cutover and remaining decisions

1. **Shadow on one repo.** Prove local OTLP/JSONL parity and pi parsing with synthetic/replayed fixtures first. Include duplicates, partial frames, `/clear`, fork/resume, nested agents, cache TTL splits, errors, compaction, private fallback, stream crash, disk full, kill, clock skew, outage and replay. Verify races for two colleagues claiming the last slot, replays after restart, stale lease, policy lowering while active and windows rolling with work in flight. Read-only research did not run these tests.
2. **Canary one normal cloud mob with consent and approved ingress.** Bind its remote ID before admitting sprites. Check request events, opt-in metrics, lifecycle hook coverage, setup/restore, terminal loss, session reuse and source freshness. Rehearse denial and intervention without assuming a telemetry outage means zero. If no secure connection, accept only lifecycle mirroring and yellow/unknown spend, or move the lane to a controlled runner. This is a product decision under Q3, not a parsing fix.
3. **Turn on admission limits before autoscaling.** Start with concurrency, deadline, retry and per-task caps; enable modeled spend and account quota gates with alerting. Enable strict token/financial ceilings only for lanes with verified request-level control and a defendable bound. Keep emergency human stop available on the office host and test a host/board outage. Add Phoenix/Langfuse only if inspection of execution traces, rather than balances, becomes a bottleneck.

**Unsolved:** exact per-task share of a fixed subscription or account quota; exact charges at a finer grain than provider reports; fully observed provider work after a lost response/export; hosted VM metering and immediate cloud termination; version/plan coverage for cloud hook delivery or any unsupported fallback; exact attribution of requests deliberately spanning tasks; exact human attention. The inspector must say which of these is unknown. The jockey should choose whether to keep the convenient hosted lane with those limits or require the controlled lane for work that needs strict accounting.
